in: recover Ctrl+Space/Ctrl+@ on legacy terminals

A terminal with neither the kitty keyboard protocol nor modifyOtherKeys
(a default tmux, for instance) sends Ctrl+Space and Ctrl+@ as the single
NUL byte 0x00. load_ncinput() normalizes C0 bytes 1..26 to Ctrl+letter but
leaves 0 alone, so the event is queued with id == 0 -- and notcurses_get()'s
return-value contract uses 0 for "no input", which makes a NUL keypress
unrecoverable by any caller: a notcurses_get_nblock() drain loop has to
treat 0 as queue-empty.

The byte can only be saved inside the library, before it is queued.
Normalize it to id ' ' plus NCKEY_MOD_CTRL -- exactly the shape a
kitty-protocol or modifyOtherKeys terminal already reports for Ctrl+Space --
so callers see one consistent event regardless of terminal capability.
